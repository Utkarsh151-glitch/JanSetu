# Phase 3B implementation plan

Baseline: app 0.3.0, 7,347 websites, 25 services, 3,823 pending website cases. Source/review hashes are captured in `data/validation_reports/phase3b-baseline.json`. Existing Compose navigation, catalog indexing and signed catalog updates remain the integration points. LocalSettings is preferences only; no existing database, notification channel, scheduling library or account exists. Backup is disabled but explicit transfer rules are absent.

1. Add a repository interface and SQLiteOpenHelper implementation. Use transactional application/history tables, a tested additive schema migration, encrypted payloads with Android Keystore AES-GCM, and a database under `noBackupFilesDir`. Never destructively recover a damaged database. Surface unreadable records and preserve their bytes until deliberate removal. Retain service identity/jurisdiction/official-link snapshots separately from user-editable fields.
2. Add My Applications navigation, filtered/sorted lazy list, manual and service-prefilled editors, detail/history, confirmed individual/all deletion and optional reference reveal. Keep drafts through rotation with saveable state; persist only on explicit Save. All database operations run on IO.
3. Use inexact AlarmManager reminders at 09:00 in the device timezone, optionally 0/1/3/7 days before a deadline. Request Android 13 notification permission only on user action; check notification/channel settings. Unique PendingIntents replace earlier schedules. Re-read records at delivery and persist a duplicate guard. Reconcile after boot/timezone/clock changes and app resume. Generic notifications contain no application title, reference or notes. No exact-alarm permission or network requirement.
4. Gate both Apply and Add from service pages on published/verified, online, confirmed official application routes. Manual entries remain available. Never infer submission from a browser action. Add privacy/backup rules and document local-only sync/status boundaries.
5. Test model/date/history/filter/reminder policy on JVM; SQLite CRUD, reopen, migrations, damaged records, encryption and scheduling on emulator; Compose service-to-tracker/manual/edit/delete flows. Run existing Python/Node/JVM/lint/debug/emulator suites, preserve catalog hashes, install current APK, inspect normal/narrow/large-font flows and record actual evidence.

Platform references checked before implementation: [inexact alarms](https://developer.android.com/develop/background-work/services/alarms), [notification permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission), [cryptography](https://developer.android.com/privacy-and-security/cryptography), [backup exclusions](https://developer.android.com/identity/data/autobackup), [SQLiteOpenHelper](https://developer.android.com/reference/android/database/sqlite/SQLiteOpenHelper).

No cloud login, database, sync or live government-status API is included. Schema version 1 is an explicitly tested initial tracker layout; version 2 adds only duplicate-delivery bookkeeping. There is no released tracker database to import.
